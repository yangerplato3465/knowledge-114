# 暮光森林｜共用世界觀與遊戲設計準則

**製作每款遊戲前必讀。** 本文件定義共用 IP 的角色、世界與遊玩體驗；新遊戲預設沿用。各遊戲文件只補玩法、教材與場景差異，不另寫一套共同設定。既有遊戲修改前也須閱讀，但不因此自動更換其世界觀、UI 或已定案玩法。

[文件總覽](../README.md) · [角色圖鑑](characters.md) · [原圖與素材](art/README.md) · [各遊戲設計](../games/README.md)

## 1. 世界：用知識照顧彼此

暮光森林是人類與擬人動物共同生活的溫柔魔法世界。魔法工坊是居民交換委託、修補日常的小小據點；玩家是受邀一起幫忙的夥伴，米洛陪玩家觀察、嘗試與完成心意。

- **生活尺度的冒險**：點亮回家的路、寄出請帖、照顧種子、修好物件。可以有謎題與小意外，核心是好奇、合作與修復，不靠恐嚇、羞辱或災難逼玩家前進。
- **世界會回應行動**：完成任務後，燈亮了、信送到了、朋友安心了。知識有具體用途，居民也有工作、偏好與彼此的牽掛。
- **魔法提供想像，知識遵守規則**：容量、數量、因果與學科概念必須正確；奇幻設定不能偷偷改變解題條件。虛構草藥與配方不作真實醫療或實驗指示。
- **可延伸的場所**：已實作魔法工坊與星燈小徑（含守燈亭、夜花坡、石橋舊郵路）；森林郵局、草藥園、修理屋仍是擴充方向，不代表已實作。不同遊戲可發生於不同時段，不必永遠是黃昏。
- **一致的情感承諾**：慢慢想也受到歡迎。失敗留下線索，再試一次有意義；角色感謝玩家的幫忙，不把步數或分數當成人的價值。

## 2. 固定角色：身分、口吻與辨識

角色身分、個性、口吻與外形統一見 [角色圖鑑](characters.md)，製作時從圖鑑選取原圖，不從舊截圖猜造型。

外形、服裝、比例與代表道具以[現役角色素材](../../src/games/magic-workshop/art.ts)及[角色原圖](characters.md)為基準，不因換遊戲任意換物種、性格或辨識特徵；案件需要的服裝變化記在該遊戲文件，未產製的變裝不能當成現役原圖。新角色須有明確生活職責、辨識特徵及與既有角色的關係；不必每款遊戲都讓全員登場，也不固定五位客人的出場順序。

## 3. 世界風格：可走進去的繪本

- 延續魔法工坊的細緻手繪奇幻插畫：圓潤親切的角色、木頭、玻璃、紙張與布料；暖光搭配靛紫暮色、青綠魔力與少量金色亮點。原圖、配色與製作來源見[美術索引](art/README.md)，新場景可換主色，但保留材質與光影語言。
- 場景有連續空間、前後景與生活痕跡。角色站得住、道具有接觸陰影；視角、光源、比例一致，重要操作區保持清楚。
- 動作有重量與因果：拿起、移動、放下、發生變化；待機動態輕柔，聲音陪伴操作。裝飾、光暈與演出不得遮住題目、數值或出口。
- 文字使用清楚的繁體中文與圓潤字形，目標比閒聊醒目。文案配合既有空間分段，不能靠縮小字級塞滿；魔法工坊的短句規格見[故事來源](../../src/games/magic-workshop/story.ts)，不強迫其他遊戲照搬尺寸。

## 4. 遊戲設計：讓玩家操作世界

**主要畫面必須是一個可玩的場所。** 把背景換成插畫，再疊網頁卡片與答題表單，不算完成本 IP 的遊戲設計。

1. **先有居民的需要，再有學習任務。** 開場用一個事件交代「誰需要幫忙、為什麼、做到什麼算完成」，不用長篇設定或課程介紹擋住開始。
2. **知識直接成為動作。** 量取就操作瓶子；分類就整理郵件；排序就安排路線；推理就觀察現場與比對線索。這些是設計例子，實際規則須符合教材。避免把答選擇題當作任何玩法的唯一開關。
3. **資訊長在場景裡。** 任務可在訂單或信件上，進度由修好的物件呈現，操作是道具、木牌或場景機關。書本、地圖、背包可以承載選擇，但不能只是替儀表板換皮；禁止以網站側欄、卡片網格、分頁表單堆出主遊玩區。
4. **教學就在第一次操作。** 先示範一個安全動作，立即讓玩家試；保留清楚的短提示與分層協助。主循環為「看見需要 → 觀察／規劃 → 操作 → 看見結果 → 完成委託」，關數與節奏由玩法決定，不一律套五關或三顆星。
5. **回饋先講結果，再談評價。** 成功先讓世界改變、角色回應；失敗說明發生什麼，提供復原、重試或等效補救。挑戰可以有難度，但不默認倒數壓力、公開排名或一次失誤整局歸零。
6. **彩蛋是關係與發現。** 用前後呼應的台詞、生活小物與角色習慣，讓細心的玩家多懂一點世界；不影響必需答案、不誘導錯誤操作，也不要求刷失敗才能看到。隨機故事需有一致的選取方式，重玩不因重繪跳台詞。

沉浸感不犧牲可用性：滑鼠、觸控、鍵盤皆能完成核心操作，拖曳須有點選替代；焦點畫在對應物件上，目標不能只靠顏色或聲音辨認。全螢幕內可退出，手機重排仍看得清、碰得到；減少動態不改玩法。Pixi 承載場景表現，DOM 保留可存取的語意、題目及操作，不要求它呈現為可見的網頁面板。

## 5. 每款遊戲開工前，寫清楚這六件事

在該遊戲的設計文件用短段落記錄，不另複製本文件：

- **一句話委託**：誰、在哪裡、需要什麼幫忙？
- **學習目標**：玩家必須理解什麼；如何從操作證明理解？
- **核心操作與規則**：操作哪些物件、如何成功、無效操作怎麼回應？
- **場景草圖**：角色、目標、操作、進度、提示與出口各在哪裡？手機如何重排？
- **故事與彩蛋**：開場、過程、收尾如何連接；至少一個角色細節前後呼應？
- **試錯與驗收**：如何求助／重來；需要哪些規則測試與實際遊玩確認？

交付前確認：**能說出它為何屬於暮光森林；學習確實發生於操作；畫面是一個場所而非網頁面板集合；故事、可讀性與各種操作方式都經驗收。** 實作與素材安全規範遵循 [AGENTS.md](../../AGENTS.md)，單款遊戲的數值與細節以其設計文件及程式為準。
