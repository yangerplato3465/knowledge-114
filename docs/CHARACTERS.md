## 數學勇者 · 勇者

`PLAYER_LOOK`（`assets/js/math-rpg.js`）

| 欄位 | 值 |
|---|---|
| 名稱 | 勇者 |
| Emoji 後備 | 🧙 |
| 站姿 | `assets/images/math-rpg/hero.webp` |
| 攻擊分鏡 | `hero-atk1.webp`（0.16）、`hero-atk2.webp`（0.34） |
| 基礎血量 | 120（可被強化提高） |

**攻擊只有兩幀，是砍過的結果。** 原本規劃四幀（起手／斬上／斬下／收招），
實作時砍掉後兩幀：「斬下」跟「斬上」在 AI 生圖手上差異太細，每次都畫成斬上的變體；
「收招」寫成「接近中立站姿」之後等於沒有資訊量。而且 CSS 的 `.lunge` 會把角色
平移出去再平移回來，**回程本身就是收招**，顯示站姿讀起來完全自然。

**劍氣是獨立的一張圖，不畫在勇者身上。** 這不是美術偏好而是流程限制：
去背腳本抓的是「全圖不透明像素的外框」再正規化高度，特效畫進角色圖會把外框撐大，
角色本體就被等比縮小（小巨龍的火焰踩過這個坑）。獨立之後還能自己做飛行與淡出。
見 [ART_STYLE.md](ART_STYLE.md)。

## 偵探事件簿 · 大耳狗喜拿（助手）

跨兩個案件的固定角色，也是整個網站的吉祥物（`assets/images/logo.webp`、favicon）。
在遊戲裡是**對話框左側的頭像，點下去給提示**，不出現在場景中。
由各案的 `CASE.assistantImg` 指定圖片。

## 偵探事件簿 · 黃金貓頭鷹案

| 角色 | 資產編號 | 說明 |
|---|---|---|
| 校長 | NPC01 | 場景中的立繪 `president.webp`，判定框跟著立繪走 |
| 五位嫌疑人 | UI03A~E | 黑板上緣一橫排的證詞紀錄表，**不用點就看得到** |

證詞紀錄表常駐顯示是刻意的設計 —— **任何「卡關會用到」的資訊都必須能重看**，
這是 [detective-authoring.md](detective-authoring.md) 的第一條原則。

## 偵探事件簿 · AI 展覽館案

嫌疑人在**全息審訊室**用 `interrogate` 謎題呈現：讀證詞 → 點可疑字詞追問 →
露出破綻才能出示物證 → 三段防線（鎮定／動搖／崩潰）。梅森是崩潰後給出關鍵線索的角色。

審訊介面的硬規則：「已釐清 / 尚未釐清」必須常駐顯示在嫌疑人卡片上
（`interrogation.js` 開頭的註解）。

## 極速博物館 · 學者

沒有個體，是**資源單位**。起始 3 人，靠升級卡增加。
保底 2 人（`TUNING.minWorkers`）—— 低於 2 就感受不到「平行」這件事，
整個教學目的就沒了。

## 班級 RPG · 學生角色

每個學生一個 Firestore 文件，存在 `classes/{classId}/students/{studentId}`。
性別對應 emoji：女 🧝‍♀️ / 男 🧙‍♂️ / 其他 🧚。

遊戲端的角色用 **Mana Seed Character Base** 素材
（`assets/images/char/char1.webp`，512×512，8×8 格，每格 64×64）：

- 上半 rows 0–3：`stand` = col 0（cols 1–2 push、3–4 pull、5–7 jump，**尚未使用**）
- 下半 rows 4–7：`walk` = cols 0–5 六格循環
- `run` 是 walk 循環把第 3、6 格換成 cols 6–7，欄序 `0,1,6,3,4,7`
- 方向列順序一律 **下、上、右、左**
- `scaleMode = 'nearest'`（像素圖不能被平滑）
