# 魔法工坊：量取魔力液遊戲設計

## 定位與目前決定

本文件記錄遊戲方向與原型驗收依據。網站已有獨立可玩原型：五關題組、操作練習、量取規則、最短解驗證、分層提示與 Pixi 動態工坊場景；題庫結構與教室節奏仍待實際試玩調整，已接入可愛夢幻風格的工坊、客人與操作區圖片。參考影片的量水玩法約作為二星入門程度，本遊戲正式題目從三星開始，著重更長的規劃、不同的解題方式與可重複遊玩的關卡組合。

- 主題為魔法工坊。玩家扮演學徒，替來訪角色量出委託所需的魔力液；角色、委託及完成演出提供情境，不改變容量規則。
- 主要使用情境是一台大電視觸控、全班觀看與討論、學生代表輪流操作；一局暫以五關、約 10～15 分鐘為設計目標，實際時長須經教室試玩確認。
- 開局先選三星、四星或五星；五關維持所選星級，以相近難度、不同解法為主，後關可略有挑戰，不要求逐關嚴格變難。各星級題目的最短解分別為 5～6、7～8、9～10 步。星級表示題目難度，不等於通關評價；最短步數不是操作上限。
- 可依題目使用二至四個瓶子；增加瓶子不自動提高星級，必須重新計算最短解並驗收思考負擔。
- 隨機遊玩須改變解題結構，不只改容量、目標數字、顏色或角色。每局從不同解題類型挑題。

## 基本規則與計步

每關提供容量固定且可見的魔法瓶。所有瓶子從空瓶開始；基本目標是讓**任一瓶**恰好裝有委託指定的整數單位魔力液。以下每一次有效操作各算一步：

1. **魔力泉（補水區）**：指定一瓶，直接補到該瓶容量上限。
2. **回收釜（倒水區）**：指定一瓶，將其中的魔力液**全部**倒掉；不允許只倒出任意數量。
3. **瓶子互倒**：指定來源瓶與目的瓶，持續倒入，直到來源瓶空了或目的瓶滿了；不允許在中途任意停止。

對已滿瓶補水、對空瓶倒水、向已滿瓶倒入等不改變狀態的操作應禁用，且不計步。液體單位為整數，不混色、不蒸發，瓶子容量在一關內不變。達到目標時先顯示已成功，再由玩家確認交付；交付本身不計步。這些定義也是關卡求解器、提示及步數評價的共同依據。

補水區與倒水區是對等的重要工具。倒水區並非失誤處理：有些題目的關鍵是主動捨棄一瓶液體，製造空位，再補水或互倒，最後留下目標量。

## 難度與瓶數

| 難度 | 最短解 | 瓶數方向 | 設計重點 |
|---|---:|---|---|
| ★★★ 學徒 | 5～6 步 | 五關二瓶 | 以累積與騰空交替練習，整局維持同一層級 |
| ★★★★ 魔法師 | 7～8 步 | 前三關二瓶，最後兩關三瓶 | 需要有意識地騰空、暫存或改變主瓶用途 |
| ★★★★★ 大魔導師 | 9～10 步 | 五關三瓶 | 需維持一段操作計畫，辨認看似退步但必要的中間狀態 |

程式設定以 [`DIFFICULTY_SETTINGS`](../src/games/magic-workshop/puzzles.ts) 為準，抽題與驗題共用此設定；選級畫面只呈現星級、稱號與奇幻冒險描述，不顯示瓶數或最短步數。四瓶保留為後續題型；目前不加入，以免同一星級的操作負擔突然增加。每個三瓶候選題都檢查移除任一瓶後無法用相同或更少步數解出，確保第三瓶確實參與最短解。

1～2 步的題目僅用於首次操作教學；參考影片程度的短題不納入正式三星。正式關卡若低於對應門檻，應重新選題，不能靠畫面文字或動畫把題目說成更難。二瓶、從空瓶開始且任一瓶達標的基本規則，常見最短解落在偶數步；因此 5、7、9 步題可能需要三瓶或其他經明確定義的合理目標形式。題庫不必強求每個星級的兩個步數各占一半。

瓶子越多，可能出現更多策略，也可能出現更短的捷徑。新增瓶子後必須從頭求解，不能沿用原題星級。四瓶題只收錄能在大電視上清楚辨認、且第四瓶確實參與有意義解法的少數關卡；不以四瓶作為五星的硬性條件。避免用大數字、密集刻度或反覆增加瓶數來代替有趣的推理。

難度除了最短步數，也須看：是否需要使用回收釜、需要預想幾步、是否有誤導但可理解的岔路、最短解是否有多條、瓶子在解法中是否有不同角色，以及學生能否從畫面清楚辨認當前狀態。額外限制（例如指定交付瓶或步數挑戰）可留作後續變化，首版不以禁用基本操作堆難度；若加入限制，求解器與畫面都須使用同一規則重新評級。

## 解題類型與題庫多樣性

題庫至少區分以下解題結構；名稱是製作與驗收用標籤，不必呈現在學生畫面：

| 類型 | 解法核心 | 驗收時要注意 |
|---|---|---|
| 反覆騰空 | 小瓶多次補滿與倒空，逐步在另一瓶留下差量 | 不能只換數字重複同一串操作 |
| 暫存接力 | 第三瓶先保存一部分液體，稍後倒回或轉給別瓶 | 第三瓶不能只是裝飾，也不能意外提供捷徑 |
| 先製造空位 | 先倒掉一瓶，讓下一次互倒停在需要的數量 | 倒水須是策略上的關鍵，而非單純修正失誤 |
| 主瓶換手 | 前段在某瓶累積，後段改由另一瓶保存或交付目標量 | 瓶子的功能在解題過程中確實轉換 |
| 多路比較 | 同題存在不同可行路線，可討論其步數或思路 | 不因有較長解法就把簡單題誤標為高星級 |

這些類型可重疊；不要求每題恰屬一類。要比較的是**解法的結構**：哪些瓶子負責累積或暫存、何時補滿與倒空、是否重複相同循環、是否存在角色轉換。容量數字、瓶子排列或故事不同，但操作骨架近似的題目，應視為同一家族，不要連續抽進同一局。也要避免只收錄一條標準答案：學生走出其他正確路線仍可通關。

## 關卡產生與選題

目前以離線枚舉、求解驗證的題庫抽題。執行 `node --experimental-strip-types scripts/magic-workshop-bank.mjs --write` 更新產出，`--check` 檢查一致性；產生器輸出每個星級／關次的候選題數與最短操作序列組數。容量保持 2～14、依大小排序且排除等比例放大；三瓶題移除任一瓶後都無法保留同長或更短的解。題庫記錄容量、目標、步數、符合的解法特性與操作序列組別，實際來源為 [generated-bank.ts](../src/games/magic-workshop/generated-bank.ts)。解法特性由最短路線判定，可重疊，不等同經教室驗證的心理難度。

各關從符合星級、瓶數及解法特性的題目中選取；同局不重複完全相同的題目，能選擇時避開上一關相同的最短操作序列組。各關題庫可能重疊，不能把五關候選數相加當作獨立題目總數。新委託會依本機保存的各星級／關次最近六題避重複，最多搜尋 256 個種子後採重複最少者；儲存不可用時仍能開局。輸入重玩代碼與「再挑戰一次」保持確定性，不受近期紀錄影響；本版題庫擴充後，先前版本的代碼不保證對應舊題。三星兩瓶的最短操作結構有限，數字變化不能宣稱是全新玩法。

產題／驗題流程：

1. 依瓶數與容量範圍產生候選容量及目標；排除目標本身等於某瓶容量等一補即成的題目。
2. 從全空狀態出發，用廣度優先搜尋列舉補滿、倒空、互倒後的狀態；狀態為各瓶目前液量。使用與實際遊戲完全相同的規則，求出是否有解及真正的最短步數。
3. 保留落在星級門檻內的題目；另外檢查最短路線是否有不同型態及是否有意外捷徑。若某題有多條最短路線，不能只看第一條就斷定其解題類型。
4. 依操作序列與瓶子用途建立相似度／家族標籤，再人工驗收是否具有不同的思考方式、畫面是否易讀、提示是否能清楚表達。
5. 每局抽題時同時限制星級、解題家族與近期重複；隨機種子可重現，方便重播與排查題目問題。

若某個星級或解題類型的有效題目不足，先補齊題庫與人工驗收，不降低求解檢查。用同一容量組合換目標數字可以是新題，但只有解題方式也有實質差異時，才算提供重玩價值。

## 一局流程與回饋

一局暫定五關：開局先選三星、四星或五星，五道正式題均維持所選星級，並從題庫抽選。三星固定二瓶，採累積與騰空兩類交替，不強求五種解題結構；目前候選題最短解均為 6 步。同星級五關維持相近難度，以解法變化提供進展感，後關可略有挑戰；不要求最短步數或搜尋指標逐關增加，第五關也不可超過所選星級的最短解範圍。首次遊玩可先用 1～2 步教學題示範操作；若不需教學，可直接進入五道正式題。實際關數、時長與難度體感以教室試玩結果調整。每關先顯示顧客委託與目標量，讓全班預測下一步，再由代表操作。成功時交付藥劑、讓顧客或工坊裝置出現簡短回饋，隨即進入下一關。

只要達標即可通關；達標後與五關成果皆顯示最短步數及一至三星的**通關表現**：最短步數完成得三星，比最短解多一至兩步得兩星，其餘完成得一星。兩星寬限以 [`TWO_STAR_ALLOWANCE` 與 `performanceStars`](../src/games/magic-workshop/session.ts) 為準。通關表現與題目的三星／四星／五星難度分開標示；各題確切最短步數在達標後公布。評價按目前保留的操作步數計算，復原移除該步、重試歸零、提示不額外扣星；操作練習不評星。支援復原一步、重試本關與可逐層展開的提示；提示先引導思考，再視需要指出下一個可行操作。不要以倒數計時、扣分、整局歸零或只能照標準路線操作來懲罰試錯。若提供「挑戰最少步數」，應是成功後可自行選擇的目標。

## 大電視觸控畫面方向

現有介面支援自適應：桌面將魔力泉與回收釜放在瓶子兩側，窄螢幕改放到瓶子下方；客人委託、目標量、難度與控制區依寬度重排，瓶子按二／三瓶數量等比配置。斷點與尺寸以 [magic-workshop.css](../src/games/magic-workshop/magic-workshop.css) 為準。小螢幕允許垂直捲動，保留完整資訊，不強求全部內容塞在一屏；教室大電視的實際視距、觸控與效能仍需實機驗收。

畫面文案以玩家當下的目標與操作為主：使用工坊、客人與委託的語氣，主畫面保留目標量、題目難度、已用步數與操作提示。完整玩法與評星門檻收在可展開說明；重玩代碼僅放在首頁重玩入口與成果頁的保存說明，不在遊玩中顯示抽題或測試資訊。進度列顯示挑戰狀態，題目難度與完成後的通關表現分開呈現。

畫面是魔法工坊的工作桌：中央以大尺寸排列當關瓶子；一側是魔力泉，另一側是回收釜；上方固定顯示顧客與「需要幾單位」的委託；下方顯示目前步數、復原、重試及可展開的操作紀錄。版位隨二至四瓶調整，四瓶時仍須能清楚區分瓶身、容量和目前液量，不讓裝飾擠壓操作區。

操作以拖曳瓶子為主：拖到魔力泉補滿、回收釜倒空，或另一瓶互倒；高亮可用目的地並在放開後執行一次操作。放到空處、無效目的地、按 Escape 或收到取消事件均不計步；失焦、切關與離頁清理拖曳。保留「先點瓶子、再點目的地」及鍵盤操作。液面高度、目前數值、容量上限及選取狀態必須始終清楚；倒入動畫短而可略過，不讓全班等待。介面須能以鍵盤與觸控操作，並沿用網站的明／暗／系統主題及動態效果降級設定。

美術可朝溫暖、帶神祕感的工坊發展：魔法瓶、發光液體、來訪角色與完成委託後的簡短場景變化。目前採用可愛夢幻動畫風格，暖金、青綠與薰衣草紫配色。若使用產圖，角色與裝飾不能遮住容量及操作資訊；瓶內液量與刻度應由程式按真實狀態呈現，不依賴固定圖片。正式產圖前須先定義尺寸、排列、錨點及安全留白，逐張與逐格驗收，避免素材跨格或被切斷。

## 動畫、音訊與驗收

特效沿用既有圖片與 Pixi：

1. **操作回饋（已實作）**：拿起陰影、有效目的地提示、放錯短距離回位、朝目的地傾瓶、瓶口光流與真實前後液量同步，以及魔力泉聚光／回收釜吸入。動畫時長以 [`OPERATION_MS`](../src/games/magic-workshop/motion.ts) 為準；數值與操作立即生效，不等待演出。新操作、復原、重試與離頁清理動畫；背景分頁與減少動態偏好直接呈現結果。
2. **完成演出（已實作）**：客人收藥、反應圖比例與腳底校正、淡入致意、星星依序亮起及學徒慶祝。完成與重玩按鈕須立即可用。

交付後的收藥卡保留上一位客人與飛入藥水，由右下角浮出，成果頁沿用同一對話框；不預留版面空間，出現／收起不推移操作區，除關閉按鈕外可穿透操作。下一關立即開放操作；可略過、逾時自動收起，新操作／重試／回首頁取消。五關成果以學徒反應圖慶祝，星星按實際評價依序亮起，未獲得的星保持空心；減少動態直接顯示最終狀態。時長以 [`motion.ts`](../src/games/magic-workshop/motion.ts) 與 CSS 為準。

五位客人的委託、達標與感謝台詞各有口吻：露米活潑、奧利俐落、諾爾沉靜詩意、菲恩靈巧自信、布諾熱情厚道；台詞由 [`art.ts`](../src/games/magic-workshop/art.ts) 統一管理，感謝框搭配各自的識別色。

有效的補滿、互倒、回收、達標與交付各有短音效，以 Web Audio 即時合成，不載入外部音檔，也不設靜音按鍵。音高、音量與時長以 [`workshop-audio.ts`](../src/games/magic-workshop/workshop-audio.ts) 為準；無效操作、提示與選取不出聲。音訊僅由使用者操作啟動，新操作取代舊音效，復原／重試／回首頁取消待播聲音，背景分頁停止，離頁關閉音訊裝置；音訊被瀏覽器阻擋或裝置不可用不影響遊戲。

瓶內晃動與零星拖曳尾光已接入；尾光限量、短暫保留，工作桌無選取或演出時停止動畫迴圈。角色走路、自然眨眼、大範圍模糊與密集背景粒子暫緩。效能要求：依顯示尺寸準備素材、按需載入並預載下一位客人；限制粒子與同時運行的效果、背景分頁停止動畫；遵循減少動態偏好，降級不影響題目、步數或操作。新操作、復原、切關與離頁須取消過期演出。實機效能仍需在教室觸控螢幕驗收。

### 美術素材與後續補圖

工坊學徒名為米洛；五關依序由露米（露珠採集師）、奧利（森林郵差）、諾爾（星燈看守人）、菲恩（草藥師）、布諾（火光修理師）登場。畫面將姓名與職業分開顯示，不以動物種類作稱呼；角色對應以 [`GUIDE` 與 `GUESTS`](../src/games/magic-workshop/art.ts) 為準，原素材識別與檔名保留。各星級共用角色造型，不改題目與難度。

五位客人、共用空瓶與完成藥水已產出；第二批選用檔案與提示見[素材清單](../assets/images/magic-workshop/batch-2-manifest.json)。[魔力泉與回收釜](../assets/images/magic-workshop/stations-manifest.json)已確認並接入遊戲。圖片以完整原圖呈現，依 [`art.ts`](../src/games/magic-workshop/art.ts) 的可見範圍等比配置，保留動作留白；客人共用腳底基準，身高與晃動幅度依角色設定。

本次反應與慶祝使用既有素材，不需補圖。若後續需要新素材，先定義用途、尺寸、錨點與安全留白。現況如下：

| 候選素材 | 用途／畫面位置 | 製作條件 |
|---|---|---|
| 客人開心表情或動作 | 交付藥水後的客人區 | 五位客人各一張已接入，獨立等比配置、共用腳底基準，與原姿勢淡入切換 |
| 學徒慶祝動作 | 五關成果畫面 | 已接入練習完成與五關成果，保留立即重玩操作 |
| 結算徽章 | 成果畫面的紀念裝飾 | 現有星星逐顆亮起已足夠，本版不另製徽章 |

六張反應素材均為 1254 × 1254 的單張透明 PNG，沿用既有角色設計，完整保留耳朵、尾巴、衣物、道具與雙腳；生成提示、參考原圖及實測可見範圍見[反應素材清單](../assets/images/magic-workshop/reactions-manifest.json)。這批已按各自可見範圍、共用角色身高與腳底基準接入；以短暫淡入切換與小幅致意呈現，並非逐幀動畫。反應圖載入失敗保留原姿勢，WebGL 失敗仍提供靜態反應圖。

顯示端使用完整構圖等比縮放的 WebP，原始 PNG 與製作清單保留在原始碼中，不納入 dist；尺寸、位元組與可見範圍見[顯示素材清單](../assets/images/magic-workshop/display/manifest.json)，可用 `scripts/prepare-magic-workshop-art.py`（Pillow）重建。按需載入當前客人與反應圖，並預載下一位客人；不預先下載全套。

瓶子下方加入[魔法光環](../assets/images/magic-workshop/bottle-magic-ring-v1.png)，依選取及可倒入狀態調整亮度；原圖與提示規格見[特效清單](../assets/images/magic-workshop/effects-manifest.json)。

瓶內水位由 DOM 按真實液量繪製，倒水光流、角色小幅致意與工坊光點由本地 Pixi 呈現；不以圖片固定題目液量。減少動態偏好停止角色與背景動畫；離頁清理場景，圖片或 WebGL 載入失敗不阻擋操作。

首頁與角色使用[工坊全景](../assets/images/magic-workshop/workshop-panorama-v1.png)、[學徒](../assets/images/magic-workshop/apprentice-v2.png)與[森林客人](../assets/images/magic-workshop/forest-visitor-v3.png)。實際尺寸與生成提示記於[素材清單](../assets/images/magic-workshop/manifest.json)。目前是完整單張素材的輕微變換，沒有逐幀角色動畫；原圖外框仍有 alpha=1/255 的極淡殘點，未宣稱通過完全透明外框驗收。

- 作為本站獨立遊戲頁接入 `src`，沿用共用導覽、主題與 `import.meta.env.BASE_URL`；首頁只提供介紹與入口。題目及操作由 DOM 承載，若採用 Pixi，限於場景與動畫呈現。
- 遊戲規則、狀態轉移、最短路徑與題庫篩選應可單獨測試；畫面不得自行使用另一套倒水判斷。隨機題需能用種子重現。
- 驗收涵蓋：候選題全數可解且星級正確；新增瓶子不造成未發現的捷徑；一局解題類型有實際差異；撤銷、提示與目前畫面狀態一致；大電視觸控及教室視距下可讀可點。
- 尚待定案：故事內容、是否加入指定交付瓶等變體、候選題庫數量，以及教室試玩後的每局時長與提示節奏。
