## 放置原則

| 位置 | 唯一責任 |
| --- | --- |
| `docs/world/` | 暮光森林共同設定、角色身分與造型、原始美術與來源紀錄 |
| `docs/games/<遊戲>/` | 遊戲專屬玩法／教材／場景／美術；用連結引用世界觀 |
| `docs/project/` | 網站整體設計、架構、待辦與必要的技術驗收證據 |
| `assets/images/` | 實際載入的圖片，按用途／遊戲分類；網站共用圖在 `site/`，工坊執行圖在 `magic-workshop/display/` |
| `src/`、`assets/js/` | 現役程式；規則、數值與完整台詞以程式為準，不複製到多份文件 |
| `assets/uploads/` | 教學檔案，不當作角色母圖庫 |
| `assets/vendor/`、`node_modules/` | 本地引擎／安裝依賴，不歸入世界觀 |
| `dist/` | 可重建發布產物，不編輯、不當作原稿 |
| `.art-output/`、`tmp/` | 本機中間產物／試驗；正式參考先移入對應資料夾並建立來源索引 |

新增設定先更新既有權威文件；不要再建立第二份世界總覽或把角色介紹複製到各遊戲。原稿只存一份，圖鑑直接引用；改檔名或位置時同步修正 Markdown、製作腳本及程式引用。歷史過程查 Git，產圖提示與原稿關係留在美術來源紀錄。

數學勇者的原稿、參考圖與動畫仍在 [自身素材目錄](../assets/images/math-rpg/)，其格式由 [美術規格](games/math-rpg/art.md) 管理；沒有證據的素材不自行歸入暮光森林。動畫刻意重複的幀具有時序用途，不能只按檔案雜湊去重。

## 新增與改名流程

分類依據是「內容由誰維護、誰會共用」，不是檔案格式或哪次工作產生的。因此角色設定跨遊戲共用，放世界觀；單款遊戲規則放該遊戲；網站介面與技術放專案文件。原稿用來追溯與再製，執行圖用來載入，兩者分開管理。

1. **先找再新增**：用 `rg` 搜尋主題、角色名、檔名與引用；已有權威文件就更新該處，其他位置只連結。新主題才新增資料夾，並在最近一層目錄加入入口。
2. **判定歸屬**：依上方表格選位置。暮光森林角色原稿放 `docs/world/art/characters/<角色識別名>/`；網站原稿放 `docs/world/art/site/`；世界內單一場景／遊戲的原稿按美術庫分類。獨立主題沿用自己的美術規格，不因使用相同網站入口就併入世界觀。
3. **清楚命名**：新路徑用小寫英文、數字與連字號，中文名稱寫在標題／圖鑑；文件依職責命名，例如 `design.md`、`art.md`。原稿採 `<主體>-<用途或姿態>-vN.<副檔名>`，例如 `milo-wave-v1.png`；不使用 `final-final`、`最新版` 或工具隨機檔名。既有名稱可讀且有引用時不為統一外觀而重命名。
4. **分清來源與採用**：新原稿記錄提示、尺寸、格位、加工腳本與輸出關係於該批 manifest；現役使用以程式／加工腳本的實際引用為準。新版本不自動取代舊版，未採用稿須標示；有來源價值才保留，純試驗留在本機中間目錄。
5. **連同引用修改**：搬移或改名後搜尋舊路徑，更新 Markdown、manifest、加工腳本與程式。母圖與執行圖不因內容相似而互相刪除；相同檔案先確認用途，避免破壞動畫幀序或共用載入契約。不用複製檔案修補失效引用。
6. **完成驗證再交付**：依 [AGENTS 的驗證要求](../AGENTS.md#驗證與交付) 執行檢查；涉及載入路徑時驗證兩種 base 建置。確認新資料從既有索引找得到，且未留下第二份設定、失效連結或把 `dist/` 當來源。

這裡是分類與命名的唯一規則來源；世界設定、遊戲規格、美術製作細節仍各自在所屬文件維護，不在此重複。
